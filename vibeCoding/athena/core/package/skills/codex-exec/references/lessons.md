# codex-exec — 经验与教训

来自 quantum-links 会话 BK（2026-11-19～20）约 25 次 codex 写者 / 审查者派工。

- **门禁按 verdict 放行**：CONCERNS 也不能 ship，要修完再审；只有 PASS 放行。
- **黑名单式补洞收敛不了**：同类发现连续两轮出现，就换成白名单 / 按构造失败封闭的方案（例：命令分类准入从逐个补 shell 写法，改成「原文文法 + 命令名白名单」后一轮收口）。主 agent 定方案，写者只实现。
- **简报里写死数字和名字**：迁移号预分配、并行刀各用各的号；分支名 / sprint slug 一旦撤销就不能复用（归档目录已占）。
- **`$(...)` 要真展开**：简报内容用 `"$(command cat file)"` 传入；`cat` 可能被 alias 成 bat。
- **守卫与本机状态**：`apps/*/node_modules/.vite` 这类缓存会触发「无嵌套 node_modules」守卫，跑守卫前删掉；本机常驻 dev server 可能在测试期间重建它。
- **开发库迁移乱序**：两刀的迁移先后合入、dev server 在中间跑过，会出现「unordered migrations」；dev 阶段直接回滚乱序那条再按序重跑。
- **偶发失败**：高负载下的计时类用例先单跑确认，再记 flaky，不改断言掩盖。
- **红态证据要逐条**：「整个测试文件加载失败」不算每条用例的红态；要求写者逐条记录修复前失败的断言。
