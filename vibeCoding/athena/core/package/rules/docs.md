# Docs

## 注释
- P0：公开 API 有 docstring / JSDoc；非显然的算法选择、兼容 hack（带 issue 与删除条件）、性能关键路径写明原因。
- P1：有副作用的函数、非显然的错误处理、类型断言写明为什么安全。
- 不写：复述代码、变更历史（看 git）、无 issue 号的 TODO、注释掉的代码。
- 注释放在被解释行上方；行尾注释 ≤20 字符。

## README
最小集：一句话描述、可复制运行的 quick start、主要命令。生产项目再加架构图、配置项、部署、测试方式。

## `.ai_state` 产物
| 产物 | 写法 |
|---|---|
| `design.md` | 背景 ≤5 行；方案含 ≥1 个备选对比；每条 `- ACn:` 一句、可观察；Bugfix 用三段式（当前行为 / 期望行为 / 不变行为，模板 bugfix-design.md） |
| `log.md` | 路径、stage、写集、失败、下一步；不写过程叙述 |
| `issues.md` | 一行一事，`athena issue add` 写入 |
| 决策 | ADR 模板见 pace/references/decisions.md |

## 电报体
结论先行；名词 + 动词 + 数字；表格 > 列表 > 散文。删铺垫、客套、复述输入、总结已写内容。保留验收、证据路径、风险、下一动作。引用给路径 + 行号，不贴原文。不写文言，不省略到主语不明。README 和对外 API 文档用完整句。
