# 会话末整体审查与架构降熵（Fable）

用户 2026-11-28 会话 CD 裁定：会话末由 Fable 执行一次，合并原「会话末 Fable 大审查」（阻断项、安全红线、依赖与漏洞、过度设计、架构审查）与「架构降熵」，并加上清理与瘦身。时机：会话最后、全量测试之后、发版之前；不在会话中途做（额度重置后做一次）。项目自己的命令（全量、守卫、镜像检测、legacy-scan）见项目 rules。

## 核心思想

假设今天是产品诞生的第一天，但已经知道当前所有真实需求、业务约束和产品形态。先想清楚代码库理想状态下应该是什么样，再通过安全、渐进、可验证的重构向它收敛。

## 工程属性（判据）

1. **唯一权威来源**：每种业务规则、数据定义、配置、状态与设计规范只有一个权威来源。
2. **标准实现**：同一语义、同一职责只保留一种实现。消除平行实现、重复逻辑、临时补丁、无意义兼容层与并存的多套方案；有真实调用方或明确契约要求的兼容保留。
3. **深模块**（Ousterhout）：复杂性封装在内部，接口简单稳定；减少浅模块、纯转发层与泄漏实现的抽象。
4. **高内聚低耦合**：职责、所有权、依赖方向明确；模块间走稳定契约；消除循环依赖、隐式耦合、跨层访问与共享可变状态。
5. **改动局部性**：改一个业务概念尽量只改一个位置。
6. **删除优于累积**：先问能否删掉。引入新的标准实现时，必须迁移完旧调用方并删除被替代的实现，禁止新旧长期并存。
7. **可执行的架构**：已确立的规范落成机器约束（类型、lint、AST / 守卫用例、契约测试、CI），防止回退。

**Deletion Test**：删掉这一层，复杂性是消失还是扩散到调用方？只保留真正封装了复杂性的抽象。

**禁止**：过度抽象；无价值的目录搬迁；为减行数牺牲可读性；为形式统一合并语义不同的概念；对 agent 自身加主流 agent 工具（Claude Code / Codex）没有的防御（与 coding.md「反过度工程」一致）。

## 第一段：发版审查（只读，先做）

以本会话全部 ship 与合入为范围，逐项给证据（file:line、实测命令输出；没跑的标「待验证」）：

1. **阻断项**：P0 / P1，重点查跨刀缺口（两刀各自正确、合起来出错）、合同 / 迁移顺序、默认配置下的可用性。
2. **安全红线**：静默执行高危动作的路径、越权与跨租户、密钥外泄、无人值守轮的放行面。
3. **依赖新鲜度与已知漏洞**：各仓 latest 以包管理器官方查询为证；上游无修复项列豁免与上界。
4. **过度设计审核**：对照 coding.md 反过度工程与主流 agent 工具行为，列多余的防御、配置、抽象与兼容层。
5. **架构审查**：依赖方向、循环依赖、跨层访问、状态所有权。
6. **发版就绪**：各仓 ahead 数、未推送、镜像版本检测落后项、前端过期写法扫描结果。

输出：`VERDICT: PASS | CONCERNS | REWORK` + 阻断项清单 + 备选修法。阻断项由主 agent 派写者修完再发版；其余记债。

## 第二段：架构降熵与清理瘦身（可写，在隔离 worktree 中）

### 建立地图（只读，落盘）
架构地图、依赖图、状态所有权地图、重复实现清单、技术方案清单、规范偏离清单、可删除清单。

### 逐域检查
UI 组件与设计系统 · 业务逻辑与领域模型 · API 接口与数据契约 · 状态管理与数据流 · 数据访问与缓存 · 配置与环境变量 · 错误处理与重试 · 日志与可观测性 · 权限与身份认证 · 命名、目录与模块边界 · 工具函数与公共基础设施 · 测试、构建与开发工具链。

### 清理与瘦身（每次必做）
- **死代码**：未用导出、文件、依赖（knip / 类型检查 / 调用方检索；检索式要抓得住动态 import、字符串键反射、`as unknown as`）。
- **废弃测试**：测的行为已删除、重复覆盖、长期 skip 的用例；偶发不稳的用例修根因或删除，不靠重试掩盖。
- **依赖瘦身**：重复依赖与多版本、可被已有依赖替代的、只为一处小功能引入的。
- **产物瘦身**：前端首屏 chunk 与总包体、镜像层与体积、桌面安装包；给出前后数值。
- **仓库卫生**：缓存目录、临时文件、已合并的 worktree 与分支、过期记账、陈旧文档与注释。
- **守卫基线**：size-ratchet、选中面、native 等基线只降不增，能降即降。

### 治理循环
扫描 → 发现熵与偏离 → 分析真实调用方与依赖 → 提出多个方案 → 选总复杂度最低的 → 建立行为基线与测试 → 完成一批完整迁移 → 删除被替代的旧实现 → 独立复审（与执行者异族）→ 执行验证 → 建立防回归约束 → 记录并继续。

每轮必须闭环：不许只建新抽象、新目录或新接口而不迁移原调用方。

### 执行约束
- 隔离 git worktree；每批有效改进一个 commit；遵守项目的迁移号、守卫、写者分工与 review 规则。
- 维护三份产物：进度文件、架构决策记录（ADR）、优化任务池（优先级 + 价值 / 风险 / 规模）。
- 需要产品决策、重大架构变更或破坏性迁移的事项，记为「待用户确认」，继续其他独立任务。
- 保留全部现有功能、数据兼容性与对外契约。
- 无需每轮询问；持续执行，直到高价值任务收敛、达到运行预算，或没有可安全实施的改进。
- 发版前完成的批次随本会话发布；未完成的写进任务池交下个会话。

## 验收

- 每种核心业务概念有明确的权威实现。
- 每个核心模块职责清晰、公开接口明确。
- 同一语义不存在未经说明的多套实现。
- 核心模块间没有未经批准的循环依赖。
- 业务逻辑与 UI、存储、框架和外部服务合理解耦。
- 新功能能在明确的模块边界内完成。
- 已确定的关键规范有自动化防回归检查。
- 本次清理瘦身给出前后对比（删除行数 / 文件、依赖数、包体与镜像体积、基线下降量）。
- 现有功能、数据兼容性与对外契约全部保留（全量测试、契约测试为证）。
