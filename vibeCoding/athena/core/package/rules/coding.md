# Coding

## P0
- 重复逻辑提取；magic number 用命名常量；配置不硬编码。
- 函数 ≤40 行、一件事；文件 >300 行拆分。
- TypeScript 禁 `any`、开 strict；Python 公开 API 有类型标注。
- 异常有归宿：在信任边界处理或显式上抛；禁空 catch、吞异常、unhandled rejection。
- 安全项见 security.md。

## P1 · 反过度工程
- 没有第二个消费者不抽象；没有现实需求不加配置项、参数、扩展点、flag。
- 防御只设在信任边界（用户输入、外部 IO、跨进程、权限面）；边界内 fail-fast，禁静默降级、blanket try-catch、「以防万一」分支。
- 判据：删掉后测试全绿且无真实调用方 = 删。边界缺防御仍是 P0；harness 门禁与防御纵深不适用本条。

## P1 · 量化验收先测基线
- 验收含数值门槛（行数、覆盖率、耗时、测试数）时，design 阶段先测当前值，把测量命令和结果写进 AC。
- 基线已越线：纳入本批修复，或记豁免（理由 + 上界）。禁止写一落笔就达不到的门槛。
- 并行多写者的计数 AC 写绝对相等 + 构成式（`= 基线 + 片A + 片B`），不写 `≥`。

## P1 · 可达性论证
声称「纯重构 / 无外部消费者 / 可安全删除」前，检索式要抓得住类型系统看不见的依赖：双重断言（`as unknown as`）、私有字段的运行时访问、prototype 打桩、动态 `require`/`import`、字符串键反射。原则：检索式必须能抓住该 AC 要防的那类失败。

## P1
- 函数 ≤50 行；命名有意义；错误处理风格统一；每个行为改动至少一个测试，覆盖边界。
- 对终端用户不暴露 stack trace。

## P2
- 嵌套 ≤3 层；复杂逻辑与公开 API 有 docstring。

## 例外
测试代码可放宽 SRP/DRY；第三方适配层可超 40 行；有意违反 P0 要在 PR 写理由。
