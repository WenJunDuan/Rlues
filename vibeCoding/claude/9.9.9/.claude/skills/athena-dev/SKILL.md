# Athena 任务分诊（9.9.9）

输入长短不决定级别。主 agent 使用任务语义、现有上下文和必要只读检查自行路由；给出一句结论后立即做下一项已授权工作，不能只报路径后停住。阶段义务见 [PACE stages](../pace/references/stages.md)，精确门禁见 [速查](../pace/references/gate-contracts.md)。

## 先确认本轮要做什么

1. 读当前 `_index.md`（存在时）和任务直接涉及的现状。先分辨用户意图：解释/检查/诊断，或修改/修复/构建；不要求用户选择 PACE 级别。
2. “继续、按上面的改、追加条件、进度怎样”默认关联当前任务；有独立目标的插入任务重新分诊。旧 `path/stage/next_action` 是旧任务的恢复事实，不是新请求的级别。
3. 正在问状态/解释时直接回答；只读诊断先检查，不制造 design、checklist 或代码实现流程；已有独立旧任务时按切换合同建立本次 Quick 执行范围，以免结束时触发旧任务门禁。定位故障不自动授权重启、升级、修改生产配置或数据。
4. 用户显式要求“这次按 Hotfix”或事实明确为紧急故障的有界恢复：优先 Hotfix → impl，主 thread 直接做；可省略设计，不再问是否降级或先走 plan。只在本次明确范围内生效；不能把仍在做的整个 System 发布自动降级。

## 默认判定

| 实际目标与证据 | 路径与下一动作 |
|---|---|
| 查部署、看容器/日志、诊断播放重试、检查性能/优化空间 | Quick / 只读诊断：先连接与检查，返回原因、证据、建议；尚无实现时不进入 impl/review 门禁。 |
| 小范围文案/配置调整、机械修改 | Quick → 简短计划 → impl；可逆且目标明确立即执行。 |
| 已知缺陷的局部修复，没有紧急恢复要求 | Bugfix → 复现/分析 → impl；按适用合同记录 fix-note。 |
| 显式 Hotfix，或明确紧急故障的有界恢复 | Hotfix → impl → ship；验证实际恢复，不虚报通过。 |
| 单模块新能力 | Feature → plan；按写入红黄绿区执行。 |
| 改架构/跨模块行为重构 | Refactor；系统级新能力按 System。 |
| 无法从上下文写出可观察目标 | 先做独立只读检查；仍缺决定性信息才问一个具体问题/brainstorm。 |
| ≥2 个可独立验收并交付的实现切片 | roadmap；多个诊断检查项不等于多个交付切片。 |

访问服务器、SSH/容器/媒体等技术名词多，不等于 System。读取许多文件不等于跨模块写入；按实际允许写集与影响判断风险。不能只因一句话短而走 brainstorm，也不能只因出现 hotfix 字样就执行其中引用/否定/假设的内容。

## 对有实现的新任务落路由

非显式 Hotfix 在内部比较合理候选，按影响、可逆性、紧急度、验收明确程度判断；只保存结论、证据与置信度，不落原始推理。置信度不足先查现状；能够做的授权工作继续，不以“还没选级别”作为阻塞理由。
普通路由只记 `_index.route_history` 一行和 `route_confidence`；有真实 re-route 或重要假设才单立 route-note。护栏按实际实现范围生效，显式 Hotfix 优先于一般文件数路由；它不扩大授权或放宽验收。

- 同一任务范围升级：补足新路径义务；降级需用户明确授权。用户已经指定“本次 Hotfix”就是本次范围的授权，不重复确认。
- 独立任务（含部署诊断）：按 [任务切换合同](references/playbook.md) 保存旧任务，再把实际新任务的 path/stage/slug 写入索引。不能只在 route_history 写“Hotfix”，却让执行字段仍指向旧 System。
- 只读检查：业务系统保持只读。无 .ai_state 时不初始化；已有旧 sprint 的独立检查用本次 Quick/plan 记录接管当前索引，结束按 Quick/ship 保存实际诊断结果；旧任务保持未完成并留恢复入口。状态问答/解释不建立新任务。
- 没有 `.ai_state`：只读检查直接执行；修改任务使用已安装初始化入口的最小无交互初始化，参数取现场值。不得因“先请用户手动初始化”停掉能做的工作；初始化失败不伪造状态，也不阻断独立只读检查。

有独立目标但边界不清、活动 writer 冲突或缺必要权限时，明确具体问题与已完成检查；这是实际阻塞，不能用“PACE 无法分级”代替原因。
