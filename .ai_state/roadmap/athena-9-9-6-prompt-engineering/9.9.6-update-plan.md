# Athena 9.9.6 更新计划

## 发布目标

把 9.9.3 的 PACE / `.ai_state` 双内核迁到 Claude Code 2.1.219+ 与 Codex 0.144.4+ 的当前合同，完成 Opus 5 / GPT-5.6 角色化配置、默认/过期项清理、skill/PACE/state 减重和双端行为回归。

## Gate 0 · 用户确认与编排恢复

1. 用户确认 roadmap 范围。
2. 单独确认 Codex 高权限默认是否继续：`approval_policy=never` + `danger-full-access`。
3. 重跑 subagent binding handshake；必须捕获真实 raw agent id。
4. architect 只读 inventory，main 写正式 design Round 1。
5. critic 至少两轮；PASS 前不进入实现。

退出条件：design 有明确 AC/File Structure Plan、独立 critic 证据与 PASS；`_index.stage=impl` 由 gate 允许。

## Phase 1 · 建立 baseline 与共享合同

### 1.1 先写 RED 场景

为 9.9.3 记录以下 baseline：模糊问题、Quick、Feature、System、gate block、status-only、mid-turn override、compaction recovery、skill triggering、role model resolution。

记录指标：

- task/gate correctness；
- route accuracy；
- unnecessary questions；
- implicit skill false positives/negatives；
- prompt/catalog chars；
- tool calls、wall time、model/token cost（缺失保持 null）。

### 1.2 新建共享 source

实现 `shared/9.9.6` 的 policy/stage/role/skill contracts；renderer 只产出根 prompt 与 catalog metadata，skills 正文仍为端内源。

### 1.3 validator 先覆盖结构

新增检查：

- 双端 stage/role/skill parity；
- adapter allowlist；
- skill catalog ≤6500 chars；
- 26 skills discovery；
- root prompt budget；
- stale config denylist；
- 9.9.1 已关闭 regression denylist。

退出条件：9.9.3 baseline 已保存；renderer 幂等；故意制造 drift 时 validator RED，修复后 GREEN。

## Phase 2A · Claude Code adapter（独立 worktree）

所有权：`vibeCoding/claude/9.9.6` + Claude runtime harness。不得修改 shared contracts。

1. 从 9.9.3 fork 新版本目录，不就地改旧包。
2. floor/target 刷到 2.1.219 与发布时 stable。
3. settings 删除：
   - `effortLevel=xhigh`（先由 eval 比较）；
   - `ANTHROPIC_DEFAULT_FABLE/OPUS/SONNET_MODEL`；
   - `CLAUDE_CODE_SUBAGENT_MODEL`；
   - `ENABLE_TOOL_SEARCH`；
   - `API_TIMEOUT_MS`；
   - `DISABLE_INSTALLATION_CHECKS`；
   - release-owned attribution/privacy overrides。
4. 保留 permissions/hooks/plugins，但逐项对当前 schema；不新增默认 workflow/Agent Teams 配置。
5. agents 采用角色 matrix；删除正文中的模型/effort/能力复述与 `ultrathink` 依赖。
6. skill descriptions 从 shared catalog 渲染；维护 skill 标记 explicit-only。
7. 补 exact 2.1.219 model-resolution、worktree、nested-agent policy、hook payload runtime tests。

退出条件：CC syntax/runtime/prompt eval 全绿；`opus`=>Opus 5；角色 frontmatter 未被 env 覆盖。

## Phase 2B · Codex adapter（独立 worktree）

所有权：`vibeCoding/codex/9.9.6` + Codex runtime harness。不得修改 shared contracts。

1. 从 9.9.3 fork 新版本目录。
2. floor/target 刷到 0.144.4 与发布时 stable；model resolver 再跑一次。
3. config 删除：
   - `model_provider=custom_openai` 与空 provider 表；
   - manual context/compact metadata；
   - stable default-on feature flags；
   - Experimental memories 与 warning suppression；
   - `[features.multi_agent_v2]`；
   - legacy/undocumented agent fields；
   - 26 个 skill enabled entries；
   - machine WSL 和 desktop preferences；
   - 无实证需要的 root/doc overrides。
4. `[agents]` 只使用正式 `max_concurrent_threads_per_session` 与必要默认。
5. agents 用 Sol/Terra 候选 matrix；跑相同 eval 决定最终档位。
6. 保留明确产品选择：model、plan effort、live evidence search、用户确认后的权限/沙箱。
7. 补 fresh auto-discovery、memory-off、provider、hook concurrency、role model runtime tests。

退出条件：CX config 在 exact stable 上无 warning；built-in provider；skills 自动发现；runtime/prompt eval 全绿。

## Phase 3 · skills / PACE / `.ai_state` 收敛

所有权：shared contracts、双端共用 semantic files、state template/migration。单写者执行。

1. 把 26 个 description 改为 trigger-only，CX `agents/openai.yaml` 对维护 skill 设置 `allow_implicit_invocation=false`；CC 使用当前官方等价控制。
2. `pace/SKILL.md` 只留 route overview；transition 真相落 shared stages contract/reference。
3. breadcrumb 从 canonical stage source 生成/解析，删除副本。
4. agent prompt 只保留 role judgment + input/output；sandbox/tools/frontmatter 承载能力。
5. `_index` template 缩到 ≤4 KiB；删除工具教程和 release diary。
6. 新增 `runtime-capabilities.yaml`，init/status/router consumer 带 `detected_at`。
7. 迁移低价值字段前先做 consumer inventory；历史 sprint 不重写。
8. 修复 route/history 空行与长 inline list；最近状态与 route 摘要有硬上限。

退出条件：旧项目恢复、fresh init、checkpoint、breadcrumb、gate、status、compaction 全绿；未知 evidence 语义不变。

## Phase 4 · 集成与迁移

1. 主 integration worktree 合并 shared→CC/CX adapters→state，解决 drift，不直接复制冲突文件。
2. AI migration guide 明确三类 ownership：release-owned replace、user-owned preserve、removed default omit。
3. fixture 覆盖：纯 9.9.3、带 gateway pins、custom provider、privacy flags、desktop prefs、旧 memories、混合第三方 skills/plugins。
4. fresh HOME 验安装→真实 consumer，不只验证文件存在。
5. setup/migrate 失败注入与 rollback；不打印 token/secret。
6. validator 对 N-1 baseline、tracked/untracked drift、source renderer、双端 package parity 全检。

退出条件：迁移幂等、可回滚、用户态无丢失；fresh install 无 stale config。

## Phase 5 · 运行时、review、polish、发布

建议执行证据：

```bash
node vibeCoding/scripts/test-athena-claude-9.9.6-runtime.cjs
python3 vibeCoding/scripts/test-athena-9.9.6-runtime.py
python3 vibeCoding/scripts/validate-athena-9.9.6.py
```

另跑 exact `claude 2.1.219+`、exact `codex 0.144.4+` 与 prompt A/B runner。命令名由正式 design 与实现文件确定，不能先在 release note 自证 PASS。

顺序：runtime-verify → reviewer + spec-compliance → evaluator → rework（如有）→ polish → architecture current-state update → compound learning → ship gate。

退出条件：最终数字 passN 为 PASS，所有 AC 有 admissible evidence，无 active exception/skip，worktree clean，发布包与架构档一致。

## 删除/保留速查

| 类别 | 删除 | 保留 |
|---|---|---|
| CC model | dated first-party pins、global subagent override | `best` main、dynamic role aliases、fallback chain |
| CC defaults | tool search flag、30s timeout、install warning suppression | permissions、必要 hooks、native worktree policy |
| CX model | empty custom provider、manual context metadata | `gpt-5.6-sol`、plan effort |
| CX defaults | stable feature flags、manual skill registration、experimental memories | live evidence search、经确认的 approval/sandbox |
| skills | workflow-in-description、implicit maintenance skills | 26 entries、progressive disclosure、quantum 7→2 |
| PACE | 多处 stage 复述 | 4+5 stage semantics、red/yellow/green、2+1 review |
| state | tool tutorial、release diary、stale duplicate fields | route/pointers/preferences/counts/current summaries |

## 回滚原则

- 每个 config/skill/prompt 删除组独立 commit；A/B 失败只回退该组。
- 不用静默 fallback 掩盖不支持模型或 schema；阻塞时报告 exact stderr/version。
- 9.9.3 目录不可变，可随时作为 N-1 回滚包。
- migration 先备份并验证再替换；任一端失败，两端事务一起回滚。
