# Review Packet — heredoc 感知 shell guard（rev 5 窄核）

## Decision

全文法建模路线经 4 轮审查、同因 P0×3 证伪，用户裁决改窄核：仅「首行单声明、行上无引号残留/反斜杠/注释/替换」的词法平凡形态生效——quoted 掩正文、unquoted 豁免注释剥离（封现存放行洞）；**非窄形与今日行为逐字节相等**（机械等价矩阵钉住，不再做语义推演）。未闭合不新增拦截。CX 截断修复与字节钉承接不变。

## 验收标准

| AC | 判据 |
|---|---|
| AC1 | 6 个活体误拦样本原文重放放行（先红）；窄形 quoted 正文全免疫 |
| AC2 | 窄形 unquoted 正文豁免注释剥离（现存放行洞先红后拦）；其余文本今日保守扫描 |
| AC3 | 非窄形字节等价矩阵：4 轮审查全部对抗反例 ≥13 形态新旧 analyze 输出逐一相等 |
| AC4 | 窄形判定单源 + 惰性载入 + 失败回退（缺失≠放行）；证据侧窄形/非窄形各一例 |
| AC5 | CX >4000 掩盖管道记 unknown 与 CC 同判；决策全文仅落盘截 500 |
| AC6 | 字节钉承接 + roadmap/ARCHITECTURE 窄核措辞（含证伪记录）+ 危险清单差异实写切片 9 |
| AC7 | guard/_shell-lex CC==Pi 字节、CX 同夹具同判 |

## 审查焦点

- **唯一需证明的断言**：首行=命令位置、且第 3 条约束（无引号残留/反斜杠/#/反引号/`$(`）是否足以排除一切前置与行内词法歧义——请对抗构造首行形态（如 `$V` 展开含引号?——展开发生在 bash 运行期，guard 只看字面，字面无引号即无歧义；`<<` 前的重定向/管道?）。
- 误判方向不对称性：漏掩=维持误拦（无安全损失），多掩=须被第 1/3 条封死。
- AC3 的等价矩阵是否可机械执行（同一输入跑新旧两版 guard 对比）。
- 未闭合不新增拦截相对 rev 3/4 是行为面收缩，确认无遗留承诺悬空。
